Core Game Systems (What • How • Why)

1. The Smooth Game Loop & Speed Control Delta-Time (dt) • requestAnimationFrame
WHAT: The game runs at a smooth, constant speed on any device—whether it's a 60Hz office monitor or a 240Hz gaming display.
HOW: Every frame, we measure the elapsed time (dt) between frames using requestAnimationFrame and multiply all movement speeds by dt.
WHY: Without delta-time, the character would run 4x faster on a 240Hz monitor than on a 60Hz screen, making the game unplayable!
Frame-Rate Independence Delta-Time Clamping requestAnimationFrame
2. Parkour Jumping, Double Jump & Sliding Kinematics • Coyote Time • Jump Buffer
WHAT: Responsive jumping (tap for low hop, hold for high leap), mid-air 360° somersault double jump, and sliding under low beams.
HOW: Holding Space applies continuous upward thrust for 0.16s. Pressing Space in mid-air rotates the ninja 360°. Sliding cuts hitbox height in half while keeping the feet locked firmly to the NinjaX surface.
WHY: To make controls feel ultra-responsive like Celeste, we added Coyote Time (120ms grace window to jump after leaving a ledge) and Jump Buffering (remembers a jump pressed slightly before landing).
Coyote Time Jump Buffering Variable Jump Boost Hitbox Anchoring
3. Infinite Procedural NinjaX & Obstacles Procedural Gen • Object Recycling
WHAT: NinjaX, gaps, AC units, overhead signs, and coins generate endlessly ahead of the player as you run.
HOW: New building segments are created just past the right edge of the screen, with gap sizes mathematically scaled to current running speed so every jump is solvable.
WHY: Old buildings that scroll past the left edge are removed immediately. This keeps memory usage completely flat ($O(1)$) so the game never lags or leaks memory.
Procedural Generation Garbage Collection (GC) Optimization O(1) Memory Footprint
4. Collision Detection (Platforms, Obstacles, Coins) AABB Collision • Radial Distance
WHAT: Detecting when the ninja lands on NinjaX, hits an obstacle, slides under an overhead beam, or collects coins.
HOW: Using Axis-Aligned Bounding Box (AABB) overlap for platforms and obstacles, and circular distance for coins and multiplier orbs.
WHY: Simple math formulas run in microseconds—no heavy physics engine like Box2D or Matter.js is needed for a 2D runner!
AABB Bounding Box Squared Distance Optimization Discrete Collision
5. Parallax Sunset City Background Parallax Scrolling • 3D Depth Illusion
WHAT: The cityscape looks deep and cinematic with lit skyscrapers, water towers, and blinking red spire lights.
HOW: We draw 3 separate background layers moving at different speeds: distant towers move very slowly (0.08x), mid-city moves medium (0.28x), and active NinjaX move full speed (1.0x).
WHY: Creates the optical illusion of 3D depth on a flat 2D canvas without needing 3D models or heavy graphics libraries.
Parallax Scrolling Multi-Layer Depth Relative Speed Scaling
6. Built-in Audio Synthesizer (Zero MP3 Files) Web Audio API • Procedural DSP
WHAT: All jump whooshes, slide friction, coin chimes, beast growls, and the 124 BPM synthwave bassline play with zero external audio files.
HOW: The browser’s built-in AudioContext synthesizes sine, triangle, and noise waves directly on your sound card in real-time.
WHY: Eliminates missing audio files, avoids browser CORS security errors on local files, and loads instantly with 0ms delay.
Web Audio API Oscillator Nodes Procedural Audio DSP

Top 5 Interview Questions (Simple 2-Sentence Answers)

Q1: Why do you use Delta-Time (dt) in the game loop?
Answer: Delta-time ensures that movement speed is tied to real-world clock time rather than screen refresh rates. Without it, the game would run at 2x speed on a 120Hz display and 4x speed on a 240Hz monitor.
Q2: What are Coyote Time and Jump Buffering?
Answer: Coyote Time gives a brief grace window (120ms) allowing a jump after running off a ledge. Jump Buffering stores a jump pressed slightly before landing (160ms) and fires it the moment the character touches NinjaX, eliminating input lag.
Q3: How do you prevent memory leaks in an infinite endless runner?
Answer: We actively recycle entities: objects that scroll off the left side of the screen are immediately deleted, while new ones are generated on the right. This keeps memory usage flat ($O(1)$) and avoids Garbage Collection frame drops.
Q4: How does AABB collision detection work?
Answer: Axis-Aligned Bounding Box (AABB) checks if two non-rotated rectangles overlap on both horizontal and vertical axes simultaneously. It is computationally lightweight, requiring only 4 simple comparison operations.
Q5: Why did you build the game with pure Canvas instead of a framework like Phaser or Unity?
Answer: Building from first principles provides zero-dependency portability, instant load times, full control over physics and rendering, and demonstrates deep mastery of core computer graphics and math fundamentals.
